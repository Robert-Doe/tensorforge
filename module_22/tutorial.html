04 · The Training Loop

criterion = nn.BCELoss()
optimizer = optim.SGD(model.parameters(), lr=0.05,
                      weight_decay=0.005, momentum=0.9)

for epoch in range(EPOCHS):
    model.train()                     # activates Dropout
    for X_batch, y_batch in loader:
        optimizer.zero_grad()         # ← NEVER forget this — clears old gradients
        preds = model(X_batch)        # forward pass
        loss  = criterion(preds, y_batch)
        loss.backward()               # autograd computes all gradients
        optimizer.step()              # updates all weights

    model.eval()
    with torch.no_grad():             # disables gradient tracking
        val_preds = model(X_val)
        val_loss  = criterion(val_preds, y_val)
optimizer.zero_grad() must come before loss.backward(). PyTorch accumulates gradients by default — if you forget to zero them, each step's gradients pile on top of the last, causing wildly incorrect weight updates. This is a top-3 PyTorch bug for beginners.

06 · Brain Exercise

What happens if you remove optimizer.zero_grad() from the training loop and run for 10 epochs? Would the model converge faster, slower, or diverge?

Try it — add a comment and run. Observe the loss curve.

Answer: Gradients accumulate: the gradient at step 2 is the sum of step 1's and step 2's gradients. Effective learning rate grows unbounded over epochs. On a small dataset with a well-behaved loss surface this might still converge (just with a much larger effective step size), but on most real tasks it diverges quickly — loss spikes upward as weight updates become catastrophically large.

07 · Q&A

Q: What is autograd and how does PyTorch know what gradients to compute?
Every PyTorch tensor operation is recorded in a dynamic computation graph. When you call loss.backward(), PyTorch traverses this graph in reverse (from loss back to every parameter), applying the chain rule at each node. This is why intermediate tensors don't need to be manually saved (as we did with self._cache in M17-M18) — the graph records everything automatically.
Q: What is optim.Adam and when should I use it instead of SGD?
Adam (Adaptive Moment Estimation) keeps a running average of both gradients and squared gradients, giving each weight its own adaptive learning rate. It converges in far fewer epochs than SGD on most tasks. Use Adam as the default for neural networks unless you have a specific reason (e.g., reproducing a paper that used SGD). Starting learning rate: 1e-3 for Adam, 0.01-0.1 for SGD.
Q: What does .item() do on a tensor?
It extracts the scalar value from a 0-dimensional tensor as a Python float. Necessary for logging — if you append the tensor itself to a list, PyTorch keeps the entire computation graph alive in memory. Calling .item() extracts just the number and allows the graph to be freed.
