Module 12 — Random Forests & Gradient Boosting

One detective is good. A hundred detectives voting is better.

01 · The Big Analogy — Bagging

A single Detective (Decision Tree) is smart but overconfident. She memorises the training cases so well that she gets confused by any new case that looks slightly different.

The Chief's solution: hire 100 detectives. Give each one a different random subset of the case files AND a random subset of the evidence types to examine. Then let them all vote. The majority verdict is the final answer.

No single detective sees the whole picture — but together they cover every angle. That's a Random Forest.

02 · Bagging vs. Boosting

Random Forest (Bagging)Gradient Boosting
Tree orderParallel — all trees grown at onceSequential — each tree fixes the last one's mistakes
Each tree seesRandom bootstrap sample + random featuresFull data, weighted by previous errors
SpeedFast (parallelisable)Slower (sequential)
Typical accuracyVery goodUsually better, but needs tuning
Overfitting riskLow — averaging reduces varianceModerate — can overfit with too many rounds

03 · Code

from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier

# Random Forest — 100 trees, parallel, no feature scaling needed
rf = RandomForestClassifier(n_estimators=100, random_state=42, n_jobs=-1)
rf.fit(X_train, y_train)

# Gradient Boosting — 100 sequential rounds, shallow trees
gb = GradientBoostingClassifier(
    n_estimators=100,
    learning_rate=0.1,   # shrinks each tree's contribution — reduces overfitting
    max_depth=3,         # keep weak learners weak
    random_state=42,
)
gb.fit(X_train, y_train)

# Feature importances — which evidence mattered most?
print(rf.feature_importances_)   # array of shape (n_features,)
No StandardScaler needed for tree-based models. Trees split on thresholds, not distances — they're completely scale-invariant. Unlike SVM and Logistic Regression, you can feed raw features directly.

04 · Feature Importances

After training, each tree ensemble can tell you which features it found most useful for making splits. This is one of the most practical outputs in all of ML — it tells you which pieces of evidence actually matter for predicting case outcomes.

importances = rf.feature_importances_         # shape: (n_features,)
sorted_idx  = np.argsort(importances)[::-1]   # descending

for i in sorted_idx:
    print(f"{feature_names[i]:<20} {importances[i]:.4f}")

06 · Brain Exercise

The n_estimators sweep plot shows accuracy improving as you add more trees, then plateauing. Why does it plateau instead of continuing to improve?

And why doesn't accuracy decrease when you add too many trees, unlike in KNN (where too-high k hurt accuracy)?

Answer: Each additional tree adds a slightly different perspective, but once you've covered the diversity in the data, new trees are just repeating what the ensemble already knows. The signal saturates. Unlike KNN's k (which changes the decision boundary), adding more trees to a forest only makes predictions more stable, not worse — the extra averaging can't hurt, it just stops helping.

07 · Q&A

Q: What is XGBoost and how does it differ from sklearn's GradientBoosting?
XGBoost (Extreme Gradient Boosting) is an optimised implementation of gradient boosting with second-order gradient approximations, built-in regularisation, and hardware-level parallelism. It's 10-50x faster than sklearn's GB on large datasets and often slightly more accurate. The underlying algorithm is the same; the engineering is the difference. Install with: pip install xgboost.
Q: Can I use feature importances to remove unimportant features?
Yes — this is called feature selection. If a feature has near-zero importance in both RF and GB, it's contributing almost nothing and can be dropped to speed up training. However, use caution: low importance in one ensemble doesn't mean useless in all models. Always retrain and re-evaluate after dropping features.
Q: When should I use Random Forest vs. Gradient Boosting?
Random Forest: when you want a strong baseline quickly, when training speed matters, or when you have noisy data (RF is more robust to noise). Gradient Boosting: when you need maximum accuracy and can afford slower training and careful hyperparameter tuning. In practice, try both and measure.
