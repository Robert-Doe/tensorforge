02 · Side-by-Side Comparison

SCRATCH — M05 
class LogisticRegression:
    def __init__(self, lr, epochs):
        self.lr = lr
        self.epochs = epochs
    def fit(self, X, y):
        n, d = X.shape
        self.w = np.zeros(d)
        self.b = 0.0
        for _ in range(self.epochs):
            z = X @ self.w + self.b
            p = sigmoid(z)
            e = p - y
            self.w -= self.lr*(X.T@e)/n
            self.b -= self.lr*e.mean()
    def predict(self, X):
        return (sigmoid(X@self.w+self.b)>=.5)
# ~60 lines total
SKLEARN — M10 
from sklearn.linear_model import (
    LogisticRegression
)

model = LogisticRegression(
    max_iter=1000
)
model.fit(X_train, y_train)
preds = model.predict(X_test)
# 3 lines — same math inside

Same gradient descent. Same sigmoid. Same cross-entropy loss. sklearn just hides the loop.

03 · The Unified sklearn Pattern

Every sklearn model follows the same three-method contract:

model = SomeModel(hyperparameter=value)   # 1. instantiate with config
model.fit(X_train, y_train)               # 2. learn from training data
preds = model.predict(X_test)            # 3. make predictions

Optionally a fourth:

probs = model.predict_proba(X_test)      # 4. get probability scores (not all models)

scores = cross_val_score(model, X, y, cv=5, scoring="accuracy")
print(f"{scores.mean():.3f} ± {scores.std():.3f}")

06 · Brain Exercise

Look at the CV accuracy numbers in M10 vs M09. Are they identical? If not, why might they differ slightly?

Hint: does sklearn's cross_val_score use the same shuffle seed as our M09 implementation?

Answer: They may differ slightly because sklearn's cross_val_score uses its own internal random state for shuffling folds, while our M09 implementation used RANDOM_SEED=42 with np.random.default_rng. Same algorithm, different split boundaries → slightly different fold compositions → slightly different accuracy estimates. This is normal and expected.

07 · Q&A

Q: Should I always use sklearn instead of writing from scratch?
In production: yes, almost always. sklearn is faster, tested, and maintained. From scratch is for learning — once you understand the algorithm, use the library. You wouldn't hand-solder a circuit every time you need a transistor.
Q: What is max_iter=1000 in LogisticRegression?
sklearn's LogisticRegression uses an optimiser (L-BFGS by default) that runs for up to max_iter iterations. If you get a ConvergenceWarning, increase it. Our scratch version had an explicit epochs constant for the same reason.
Q: Why does sklearn's KNN need no fit() in the traditional sense?
KNN is a lazy learner — fit() just stores the training data. The actual computation happens at predict() time. This is identical to our scratch KNN in M06, where fit() did nothing but self.X_train = X.copy().
Q: What does stratify=y do in train_test_split?
It ensures the class distribution in your train and test splits matches the original dataset. If 60% of cases are solved overall, both train and test will also be ~60% solved. Without it, a bad random split could accidentally put all the "solved" cases in training, making test evaluation misleading.
