00 · Before You Start

Prerequisites: Module 22 (PyTorch basics — nn.Module, training loop), Module 23 (what a convolutional layer does from scratch).

Install: pip install torch torchvision

Key idea: Stack two convolutional blocks (conv → relu → pool), flatten the output, and classify with a fully-connected head. Let PyTorch handle everything: autograd, batching, data loading. Expect ~98% accuracy on MNIST in 5 epochs.

Module 24 — Full CNN in PyTorch

Ada finally stops looking at pixels and starts seeing patterns

01 · The Big Analogy

In Module 23 Ada slid a single hand-crafted template over one photograph. That was useful — but she had to hand-pick the templates herself. What if she could hire a team of 16 junior detectives, give each one a blank notepad, and let them figure out which templates were most useful for solving cases?

That's a CNN training run. The 16 "junior detectives" in the first layer are the 16 convolutional filters. Their notepads are initialised to random scribbles. After thousands of crime cases (MNIST digits), each detective's notepad has converged to something useful — one might specialise in "top curves" (which separate 0, 6, 8 from 1, 7), another in "vertical strokes" (which separate 1, 4, 7). The final case verdict (which digit 0–9) is handed to a senior detective (the Dense layers) who reads all 32 junior reports.

You never tell any of them what to look for. Backprop does that automatically by adjusting the templates that led to wrong verdicts.

Two convolutional blocks extract features; the flatten + dense block classifies them. MaxPool halves spatial dimensions so 28×28 → 14×14 → 7×7. After flattening: 32 channels × 7 × 7 pixels = 1,568 values per image.

03 · The Model Code

class DigitCNN(nn.Module):
    FEATURE_H, FEATURE_W, CONV2_CHANNELS = 7, 7, 32

    def __init__(self, dropout_p=0.3):
        super().__init__()
        # padding=1 keeps spatial size the same after each conv (same-padding)
        self.conv1 = nn.Conv2d(in_channels=1,  out_channels=16, kernel_size=3, padding=1)
        self.conv2 = nn.Conv2d(in_channels=16, out_channels=32, kernel_size=3, padding=1)
        self.pool  = nn.MaxPool2d(kernel_size=2, stride=2)   # shared — no learnable params
        flat_size  = self.CONV2_CHANNELS * self.FEATURE_H * self.FEATURE_W   # 1568
        self.fc1     = nn.Linear(flat_size, 128)
        self.dropout = nn.Dropout(p=dropout_p)
        self.fc2     = nn.Linear(128, 10)

    def forward(self, x):
        x = self.pool(F.relu(self.conv1(x)))   # (B,1,28,28) → (B,16,14,14)
        x = self.pool(F.relu(self.conv2(x)))   # (B,16,14,14) → (B,32,7,7)
        x = x.view(x.size(0), -1)             # flatten → (B,1568)
        x = F.relu(self.fc1(x))
        x = self.dropout(x)
        x = self.fc2(x)                        # (B,10) raw logits
        return F.log_softmax(x, dim=1)         # (B,10) log-probabilities
Why x.view(x.size(0), -1)? After the second MaxPool the tensor is (batch, 32, 7, 7). The Dense layer expects a 1-D feature vector per image. view(B, -1) merges the last three dims: 32 × 7 × 7 = 1,568. The -1 tells PyTorch to infer the size automatically.

04 · Training Loop

# Setup
model     = DigitCNN(dropout_p=0.3)
criterion = nn.NLLLoss()                       # expects log-probabilities
optimizer = optim.Adam(model.parameters(), lr=1e-3)

# One epoch
model.train()
for X_batch, y_batch in train_loader:
    optimizer.zero_grad()
    log_probs = model(X_batch)                 # forward pass
    loss = criterion(log_probs, y_batch)       # scalar loss
    loss.backward()                            # compute gradients
    optimizer.step()                           # update weights

# Evaluation
model.eval()
with torch.no_grad():
    log_probs = model(X_test)
    preds = log_probs.argmax(dim=1)            # class with highest log-prob

The pattern is identical to Module 22's MLP — only the model architecture changed. That's the power of the PyTorch abstraction: any nn.Module plugs into the same four-step training loop.

05 · MNIST Normalisation Numbers

The transform pipeline applies Normalize((0.1307,), (0.3081,)). Where do these come from?

# These are the per-pixel mean and std computed over all 60,000 training images:
# mean = 0.1307  (most pixels are near-black — the average MNIST pixel is dark)
# std  = 0.3081  (pixels cluster near 0 or 1 — bimodal distribution)

# After normalisation:
# zero_pixel  → (0.0 - 0.1307) / 0.3081 = -0.424
# white_pixel → (1.0 - 0.1307) / 0.3081 = +2.821
Normalisation is mandatory. Without it, gradient updates for the first conv layer are dominated by bright pixels and the network trains inconsistently. We hardcode the training-set statistics here rather than computing them each run — consistent with how you would freeze preprocessing in production.

07 · Brain Exercise

The parameter table above shows that fc1 alone accounts for 200,704 of 206,922 total parameters — nearly 97% of the network. Yet conv1 + conv2 are doing the heavy lifting of recognising handwritten shapes.

Redesign the architecture to reduce the fc1 parameter count by 4× while keeping the same convolutional feature extractor. What would you change? What is the new total parameter count?

Answer: Replace fc1 = nn.Linear(1568, 128) with fc1 = nn.Linear(1568, 32). New fc1 parameters: 1568 × 32 + 32 = 50,208 (was 200,832). New total: ~56,000 — a 3.7× reduction. The accuracy drop is usually small (98.5%+ vs 99%) because the convolutional features are already compact. Alternatively, add a third conv+pool block to reduce spatial dims further before the Dense layer: 32 channels × 3 × 3 = 288 → fc1 becomes Linear(288, 64) = 18,432 params.

08 · Q&A

Q: Why NLLLoss + log_softmax instead of just CrossEntropyLoss?
nn.CrossEntropyLoss is exactly log_softmax + NLLLoss fused internally. We split them to make the pipeline visible: the model outputs log-probabilities (which you can exp() to get real probabilities and argmax() to get predictions), and the loss evaluates those. In production you'd use CrossEntropyLoss + raw logits for a tiny numerical gain. Either way the gradients are identical.
Q: The same self.pool object is called twice in forward(). Is that correct?
Yes. nn.MaxPool2d has no learnable parameters — it's a pure operation (take the max of each 2×2 window). Reusing the same object is correct and idiomatic. Contrast with conv layers, which hold weight tensors and must be separate objects so each has its own independent learned filters.
Q: Why does Adam need a lower learning rate than SGD?
Adam divides each parameter's gradient by a running estimate of its recent gradient magnitude — in effect computing an individual adaptive learning rate per parameter. If the base lr is 0.01 (typical SGD starting point), Adam's effective per-parameter update can be much larger than intended, causing instability. Starting at lr=1e-3 is the standard Adam default for most networks, equivalent to a heavily-tuned SGD with momentum in practice.
Q: What does Dropout actually do during training vs evaluation?
During model.train(), Dropout randomly zeroes each activation with probability p and scales the survivors by 1/(1-p) (inverted dropout — keeps the expected sum unchanged). During model.eval(), Dropout is a no-op — all activations pass through unchanged. This is why calling model.eval() before evaluation is not optional: without it, your test predictions are randomly corrupted and your accuracy will be lower and non-deterministic.
