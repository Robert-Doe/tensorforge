02 · Confusion Matrix from Scratch

def confusion_matrix(y_true, y_pred, n_classes=2):
    """Count TP, FP, TN, FN in a square matrix.

    Args:
        y_true: ground-truth labels (1-D int array)
        y_pred: predicted labels   (1-D int array)
        n_classes: number of distinct classes (default 2)

    Returns:
        cm: ndarray shape (n_classes, n_classes)
            cm[actual][predicted]
    """
    cm = np.zeros((n_classes, n_classes), dtype=int)
    for actual, predicted in zip(y_true, y_pred):
        cm[actual][predicted] += 1   # tally each (actual, predicted) pair
    return cm

Reading the matrix: cm[1][0] = "actual positive, predicted negative" = False Negative. That's the dangerous cell — the criminal who walked free.

03 · Precision, Recall, and F1

Why not just use accuracy? If 95% of cases are unsolved, a model that always predicts "unsolved" gets 95% accuracy and catches zero real criminals. Precision and recall expose this. 
precision = tp / (tp + fp)   # don't cry wolf — how reliable are positive predictions?
recall    = tp / (tp + fn)   # don't miss cases — how many real positives did you catch?
f1        = 2 * precision * recall / (precision + recall + 1e-9)
            # harmonic mean — punishes models that are great at one but terrible at the other

def precision_recall_f1(y_true, y_pred):
    """Compute precision, recall, and F1 for binary classification.

    Uses epsilon=1e-9 in denominators to avoid division-by-zero
    when the model predicts only one class.

    Returns:
        tuple: (precision, recall, f1) all floats in [0, 1]
    """
    EPSILON = 1e-9          # prevents zero-division when tp+fp==0 or tp+fn==0
    tp = np.sum((y_pred == 1) & (y_true == 1))   # predicted positive, actually positive
    fp = np.sum((y_pred == 1) & (y_true == 0))   # predicted positive, actually negative
    fn = np.sum((y_pred == 0) & (y_true == 1))   # predicted negative, actually positive

    precision = tp / (tp + fp + EPSILON)
    recall    = tp / (tp + fn + EPSILON)
    f1        = 2 * precision * recall / (precision + recall + EPSILON)
    return float(precision), float(recall), float(f1)

04 · K-Fold Cross-Validation

A single train/test split is like judging a detective on just one case. What if it was a lucky case? K-fold CV tests her on k different held-out sets and averages the result.

def cross_val_accuracy(model_class, model_kwargs, X, y, k=5):
    """Run k-fold cross-validation and return mean ± std accuracy.

    Args:
        model_class: an uninstantiated classifier class
        model_kwargs: dict of constructor arguments
        X: feature matrix (n_samples, n_features)
        y: labels (n_samples,)
        k: number of folds (default 5)

    Returns:
        (mean_accuracy, std_accuracy): floats
    """
    rng = np.random.default_rng(RANDOM_SEED)
    indices = rng.permutation(len(X))          # shuffle to avoid ordering bias
    folds   = np.array_split(indices, k)       # split shuffled indices into k groups

    scores = []
    for fold_idx in range(k):
        test_idx  = folds[fold_idx]            # this fold is the test set
        train_idx = np.concatenate(            # all other folds are training
            [folds[i] for i in range(k) if i != fold_idx]
        )
        model = model_class(**model_kwargs)    # fresh model every fold
        model.fit(X[train_idx], y[train_idx])
        preds = model.predict(X[test_idx])
        scores.append(np.mean(preds == y[test_idx]))

    return float(np.mean(scores)), float(np.std(scores))
Rule of thumb: k=5 or k=10 are the standard choices. k=5 is faster; k=10 gives a slightly more reliable estimate. This module uses k=5.

05 · ROC Curve & AUC

Ada doesn't just say "solved" or "unsolved" — she gives a confidence score (probability). The ROC curve asks: at every possible confidence threshold, how many real criminals did you catch (recall) vs. how many innocent people did you wrongly flag (false positive rate)?

def roc_auc(y_true, y_prob):
    """Compute ROC curve points and AUC via threshold sweep.

    Sweeps unique probability thresholds from high to low.
    At each threshold: predict positive if prob >= threshold.
    Builds (fpr, tpr) pairs. AUC = area under that curve via trapz.

    Args:
        y_true: ground-truth binary labels
        y_prob: predicted probabilities for the positive class

    Returns:
        (fpr_list, tpr_list, auc_score)
    """
    thresholds = np.unique(y_prob)[::-1]   # sweep from high confidence to low
    fpr_list, tpr_list = [0.0], [0.0]     # start at (0,0) — catch nothing

    pos   = np.sum(y_true == 1)            # total real positives
    neg   = np.sum(y_true == 0)            # total real negatives

    for thresh in thresholds:
        preds = (y_prob >= thresh).astype(int)
        tp = np.sum((preds == 1) & (y_true == 1))
        fp = np.sum((preds == 1) & (y_true == 0))
        fpr_list.append(fp / (neg + 1e-9))
        tpr_list.append(tp / (pos + 1e-9))

    fpr_list.append(1.0); tpr_list.append(1.0)   # end at (1,1) — flag everything
    auc = float(np.trapz(tpr_list, fpr_list))     # area under the curve
    return fpr_list, tpr_list, auc
AUC interpretation: 0.5 = random guessing (useless), 0.7 = decent, 0.8+ = good, 0.9+ = excellent, 1.0 = perfect (suspicious — probably overfitting).

08 · Q&A

Q: Why is accuracy misleading on imbalanced datasets?
If 95% of your data is class 0, predicting class 0 for everything gives 95% accuracy with zero predictive value. Precision, recall, and F1 all reveal this immediately because they focus on the minority (positive) class.
Q: Why use k-fold instead of a single train/test split?
A single split is sensitive to which samples land in test vs train — you might accidentally get an easy or hard split. K-fold averages over k different splits, giving a more reliable and less variable estimate of true performance.
Q: What does AUC=0.5 mean exactly?
It means your model's ranking of samples by probability is no better than random. At every threshold, your true-positive rate equals your false-positive rate — you might as well flip a coin.
Q: Can I use these evaluation functions on multi-class problems?
The confusion matrix already supports n_classes > 2. Precision/recall/F1 in this module are binary-only; for multi-class you'd compute them per-class and average (macro or weighted averaging), which scikit-learn handles automatically in Module 10.
