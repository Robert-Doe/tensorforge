Module 17 — Backpropagation

How does the last layer's mistake teach the first layer?

01 · The Big Analogy

Ada's detective agency has three departments: Evidence Collection (input layer), Analysis (hidden layer), and Final Verdict (output layer). The verdict turns out to be wrong.

The Chief calls in the Verdict department: "Your confidence score was 0.8 but the answer was 0 — you were 0.8 off." The Verdict team blames the Analysis team proportionally: "You gave me signals A and B. A was more influential — you owe 60% of the blame." The Analysis team then blames Evidence Collection proportionally.

Blame flows backward through the organisation, proportional to each department's contribution to the error. Each department adjusts its own procedures (weights) based on its share of the blame. That's backpropagation.

02 · The Chain Rule

If L depends on Z2, and Z2 depends on W2, then:

dL/dW2 = dL/dZ2 · dZ2/dW2
       = (A2 - y) · A1         # output error × hidden activation

To get the gradient for the hidden layer weights, you go one step further back:

dL/dW1 = dL/dZ2 · dZ2/dA1 · dA1/dZ1 · dZ1/dW1
       = (A2-y) ·     W2.T  ·  relu'(Z1) ·   X

Each "·" is a link in the chain. The further a layer is from the output, the more multiplications its gradient passes through.

03 · Forward Then Backward

# ── FORWARD ──────────────────────────────────────────────────────
Z1 = X  @ W1 + b1       # (n, H) — hidden pre-activation
A1 = relu(Z1)            # (n, H) — hidden output (SAVE THIS for backward)

Z2 = A1 @ W2 + b2       # (n, 1) — output pre-activation (SAVE Z1 too)
A2 = sigmoid(Z2)         # (n, 1) — predicted probability

# ── LOSS ──────────────────────────────────────────────────────────
loss = -mean(y * log(A2) + (1-y) * log(1-A2))

# ── BACKWARD ──────────────────────────────────────────────────────
dZ2 = A2 - y             # (n, 1) — output layer error
dW2 = A1.T @ dZ2  / n   # (H, 1) — output weight gradient
db2 = dZ2.mean()         # (1,)

dA1 = dZ2 @ W2.T         # (n, H) — error propagated back through W2
dZ1 = dA1 * relu'(Z1)    # (n, H) — zeroed where ReLU was inactive
dW1 = X.T  @ dZ1  / n   # (d, H) — hidden weight gradient
db1 = dZ1.mean(axis=0)   # (H,)

# ── UPDATE ────────────────────────────────────────────────────────
W2 -= lr * dW2;  b2 -= lr * db2
W1 -= lr * dW1;  b1 -= lr * db1
Why save Z1 during the forward pass? The ReLU derivative (relu'(Z1) = Z1 > 0) needs the pre-activation values. Modern DL frameworks cache all intermediate tensors in memory during the forward pass for exactly this reason — the backward pass reads them in reverse order.

06 · Brain Exercise

The 2-layer network has 65 parameters but achieves the same accuracy as the 1-layer (7 parameters). Why doesn't more parameters always mean better accuracy?

What would you need to change to make the 2-layer network outperform the 1-layer on this dataset?

Answer: More parameters create more capacity, but capacity only helps if (1) the underlying pattern is complex enough to need it, and (2) you have enough training data to fill that capacity without overfitting. Our dataset has 96 training samples and 6 features — the pattern isn't complex enough to benefit from 65 parameters vs 7. You'd need to either collect more data or move to a more complex problem (like image classification) to see the 2-layer network win.

07 · Q&A

Q: What's the difference between backpropagation and gradient descent?
Backpropagation computes the gradients (the direction and magnitude to move each weight). Gradient descent uses those gradients to actually update the weights. They work together: backprop is the "figure out which way is downhill" step; gradient descent is the "take a step downhill" step.
Q: Why do we divide gradients by n (batch size)?
The loss is averaged over all samples, so the gradient must also be averaged. Without dividing by n, the gradient magnitude would grow with batch size — making the effective learning rate batch-size-dependent. Averaging keeps the gradient scale consistent regardless of how many samples you use.
Q: Do frameworks like PyTorch compute backprop the same way?
Conceptually yes — they use the same chain rule. Mechanically, PyTorch uses automatic differentiation (autograd): it records every operation in the forward pass in a computation graph, then traverses the graph in reverse to compute gradients. You never write dZ2 = A2 - y manually. Module 22 shows this.
