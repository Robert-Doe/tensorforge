Module 08 — Naive Bayes: Probabilistic Reasoning

Beginner Named after Thomas Bayes (1701–1761). The "naive" part isn't an insult — it's an honest admission about the model's central assumption.

00 — Bayes' Theorem

Given evidence (features), what is the probability of each class? Bayes' theorem inverts the question:

P(class | features) = P(features | class) × P(class) / P(features)
posterior = likelihood × prior / evidence
  • Prior P(class) — how common is each class in training data?
  • Likelihood P(features | class) — how probable are these features if this class is true?
  • Posterior P(class | features) — what we want: probability of class given these features
  • Evidence P(features) — same for all classes, so we can ignore it when comparing

01 — The "Naive" Assumption

With multiple features x₁, x₂, ..., xₙ, computing P(x₁, x₂, ..., xₙ | class) exactly requires seeing every combination — exponentially expensive. Naive Bayes assumes all features are conditionally independent given the class:

P(x₁,...,xₙ | class) ≈ P(x₁|class) × P(x₂|class) × ... × P(xₙ|class)

This is almost never literally true — but it works surprisingly well in practice, especially for text classification. The name "naive" refers to this simplifying assumption.

The independence assumption fails when two features are highly correlated. Example: "has_gun" and "has_holster" are correlated. Naive Bayes treats them as independent, double-counting their evidence. Despite this, the model often classifies correctly even with miscalibrated probabilities.

03 — GaussianNB: Continuous Features

from sklearn.naive_bayes import GaussianNB

gnb = GaussianNB()
gnb.fit(X_train, y_train)

# What the model learned for each class:
print(gnb.theta_)    # mean of each feature per class: shape (n_classes, n_features)
print(gnb.var_)      # variance of each feature per class

# At prediction time, it computes the Gaussian PDF:
# P(xⱼ | class) = Gaussian(xⱼ; mean=θ, var=σ²)

y_pred = gnb.predict(X_test)
proba  = gnb.predict_proba(X_test)   # [[P(class0|x), P(class1|x)], ...]

04 — MultinomialNB: Text Classification

from sklearn.naive_bayes import MultinomialNB
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.pipeline import Pipeline

# Classic text classification pipeline
pipe = Pipeline([
    ("tfidf", TfidfVectorizer(max_features=5000, stop_words="english")),
    ("clf",   MultinomialNB(alpha=1.0)),   # alpha = Laplace smoothing
])

texts  = ["suspect fled north", "witness saw blue car", "stolen wallet found"]
labels = [1, 0, 1]   # 1=relevant, 0=not relevant

pipe.fit(texts, labels)
pipe.predict(["suspect ran away"])   # → [1]

05 — Laplace Smoothing

Without smoothing, if a word never appeared in class-0 training documents, P(word | class-0) = 0. Then the entire posterior becomes 0 — one unseen word kills the whole prediction. Laplace smoothing adds a small count α to every feature:

P(xⱼ | class) = (count(xⱼ, class) + α) / (total_count(class) + α × n_features)
# alpha=0: no smoothing (zero probabilities possible — dangerous)
# alpha=1: Laplace smoothing (add 1 to every count — standard)
# alpha=0.5: Lidstone smoothing (a softer version)
mnb = MultinomialNB(alpha=1.0)   # always use alpha ≥ 0.01

06 — Online Learning with partial_fit

Naive Bayes can learn from data in batches — it updates its learned statistics incrementally. This is valuable when your dataset doesn't fit in memory, or new data arrives in streams.

07 — Log-Probabilities (Numerical Stability)

Multiplying many small probabilities together quickly underflows to 0.0 in floating point. The solution: work in log-space where multiplication becomes addition.

# Instead of:
posterior = P(x1|c) * P(x2|c) * P(x3|c) * P(c)   # may underflow to 0

# Use:
log_posterior = log P(x1|c) + log P(x2|c) + log P(x3|c) + log P(c)

# sklearn does this internally. predict_log_proba() returns log probabilities:
log_proba = gnb.predict_log_proba(X_test)

09 — Q&A Brain Check

Q: Why is the independence assumption "naive" but often works anyway?
A: The theorem of optimal Bayes classification only requires correct ranking of class probabilities — not perfectly calibrated absolute probabilities. Even with correlated features, the model usually ranks classes in the right order and classifies correctly, even though its probability estimates may be far off.
Q: What is the prior P(class) and where does it come from?
A: It's the class frequency in training data. If 30% of training cases are fraud, P(fraud) = 0.30. The prior can be set manually with the priors parameter — useful when class frequency in training doesn't match real-world frequency (e.g., oversampled minority class).
Q: Why use TF-IDF with MultinomialNB instead of raw word counts?
A: TF-IDF (Term Frequency × Inverse Document Frequency) downweights words that appear in every document (like "the", "is") — they carry no discriminative signal. Raw counts treat "the" the same as a rare but meaningful word. TF-IDF sharpens the features before passing them to the classifier.
Q: Can Naive Bayes handle continuous features mixed with binary features?
A: Not directly in one model — each sklearn NB variant assumes all features are the same type. In practice: (1) binarise continuous features (pd.cut) and use BernoulliNB; (2) discretise and use MultinomialNB; (3) use a custom mixed-NB by computing log-likelihoods separately and summing them. For most real problems, GaussianNB handles mixed-type data reasonably well.
