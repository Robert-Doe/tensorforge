Module 05 — Logistic Regression: Classifying Suspects

Beginner When the answer isn't a number but a category — fraud or not, guilty or innocent — logistic regression gives you a probability and a verdict.

00 — From Regression to Classification

Linear regression outputs any real number. For classification we need a value between 0 and 1 — a probability. We get it by passing the linear output through the sigmoid function:

σ(z) = 1 / (1 + e^(-z))
P(fraud | x) = σ(β₀ + β₁x₁ + β₂x₂ + ...)

The sigmoid squashes any real number into (0, 1). Large positive z → probability near 1. Large negative z → probability near 0.

01 — Why Not Linear Regression for Classification?

Linear regression problems

  • Predictions can be < 0 or > 1 — meaningless as probabilities
  • Gradient vanishes when model is confident (MSE loss on sigmoid)
  • Assumes errors are normally distributed — wrong for 0/1 targets

Logistic regression solutions

  • Sigmoid guarantees output in (0, 1)
  • Cross-entropy loss has clean gradients everywhere
  • Maximum likelihood derivation: theoretically correct for binary targets

02 — Fitting the Model

from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

# 1. Split first (always)
X_tr, X_te, y_tr, y_te = train_test_split(X, y,
    test_size=0.2, stratify=y, random_state=42)

# 2. Scale features (logistic regression uses gradient descent internally)
scaler = StandardScaler()
X_tr_s = scaler.fit_transform(X_tr)   # fit on train only
X_te_s = scaler.transform(X_te)       # apply same params to test

# 3. Fit
model = LogisticRegression(C=1.0, max_iter=1000, random_state=42)
model.fit(X_tr_s, y_tr)

# 4. Predict
y_pred       = model.predict(X_te_s)          # hard label: 0 or 1
y_pred_proba = model.predict_proba(X_te_s)    # soft: [[P(0), P(1)], ...]
fraud_probs  = y_pred_proba[:, 1]             # P(fraud) for each sample
The C parameter: C = 1/λ where λ is the regularisation strength. Smaller C = stronger regularisation (simpler model). Default C=1. Tune with cross-validation.

  • FP (False Positive) — legitimate flagged as fraud. Annoying but recoverable.
  • FN (False Negative) — real fraud missed. The costly mistake in fraud detection.

04 — Classification Metrics

MetricFormulaQuestion answered
Accuracy(TP+TN)/(TP+TN+FP+FN)Overall correct fraction
PrecisionTP/(TP+FP)Of those flagged as fraud, how many really were?
Recall (TPR)TP/(TP+FN)Of all real fraud, how many did we catch?
F1-score2·P·R/(P+R)Harmonic mean of precision and recall
ROC-AUCArea under ROC curveOverall ranking quality; 1=perfect, 0.5=random
Accuracy is misleading on imbalanced data. If only 2% of transactions are fraud, a model that always predicts "not fraud" gets 98% accuracy — but catches zero fraud cases. Use Precision, Recall, F1, and AUC instead.
from sklearn.metrics import (accuracy_score, precision_score, recall_score,
                              f1_score, roc_auc_score, classification_report)

print(classification_report(y_te, y_pred, target_names=["Legit","Fraud"]))
auc = roc_auc_score(y_te, fraud_probs)

05 — The ROC Curve

The ROC curve sweeps the decision threshold from 0 to 1 and plots True Positive Rate (Recall) vs False Positive Rate at each threshold. A perfect model hugs the top-left corner.

from sklearn.metrics import roc_curve
fpr, tpr, thresholds = roc_curve(y_te, fraud_probs)
ax.plot(fpr, tpr, label=f"AUC={auc:.3f}")
ax.plot([0,1],[0,1], linestyle="--", color="grey")  # random baseline

06 — Threshold Tuning

Default threshold = 0.5. In fraud detection we often prefer higher recall (catch more fraud) at the cost of lower precision (more false alarms). Tune the threshold to match business requirements.

for threshold in [0.3, 0.4, 0.5, 0.6, 0.7]:
    y_pred_t = (fraud_probs >= threshold).astype(int)
    p = precision_score(y_te, y_pred_t)
    r = recall_score(y_te,    y_pred_t)
    print(f"t={threshold:.1f}  precision={p:.3f}  recall={r:.3f}")

07 — Feature Scaling Reminder

# WRONG — fitting scaler on all data before split
scaler.fit(X)                    # test data has leaked into scaler params!
X_scaled = scaler.transform(X)
X_tr, X_te = train_test_split(X_scaled, ...)

# CORRECT — fit on train only
X_tr, X_te, y_tr, y_te = train_test_split(X, y, ...)
scaler.fit(X_tr)                 # learn mean/std from train only
X_tr_s = scaler.transform(X_tr)
X_te_s = scaler.transform(X_te) # apply train params to test

08 — Q&A Brain Check

Q: Why do we use stratify=y in the train-test split?
A: With an imbalanced dataset (e.g. 15% fraud), a random split might produce a test set with only 5% or 25% fraud. Stratification forces both splits to maintain the same class ratio as the original data, giving a reliable evaluation.
Q: When should you optimise for precision vs recall?
A: Optimise for recall when missing a positive is costly (fraud detection, cancer screening — missing a case is dangerous). Optimise for precision when false alarms are costly (spam filtering — too many false alarms = users ignore it). F1 balances both equally.
Q: What does AUC = 0.5 mean?
A: The model's ranking is no better than random — it cannot distinguish between the two classes. AUC measures ranking quality: does the model assign higher scores to positive examples than negative ones, regardless of the threshold?
Q: Can logistic regression handle multi-class problems?
A: Yes. Use multi_class="multinomial" (softmax regression) for more than 2 classes. sklearn handles this automatically when y has >2 unique values. See logistic_advanced.py for the softmax derivation.
