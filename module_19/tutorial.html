Module 19 — Activation Functions

Choosing the right decision gate for your detective neurons

01 · The Big Analogy

Each neuron is a detective informant. After computing a weighted sum of evidence (z), the informant must decide how much to "shout" their signal to the next layer. The activation function is the informant's personality:

  • Sigmoid: "I'll give you a number between 0 and 1 — my confidence."
  • ReLU: "If I'm not confident (z ≤ 0), I shut up completely. Otherwise I shout exactly how confident I am."
  • Leaky ReLU: "I always whisper at least a little, even when z is negative — so I can still be trained."
  • Tanh: "Same as sigmoid but I shout in both directions: -1 means strongly wrong, +1 means strongly right."

The problem: if 10 informants all talk through sigmoid, each one's message is multiplied by at most 0.25 before it reaches the next layer. After 10 layers: 0.25¹⁰ ≈ 0.0000001. The first layer's informants receive almost no feedback and can't learn. That's the vanishing gradient problem.

02 · Activation Function Comparison

Sigmoid

Output: (0, 1)
1 / (1 + e⁻ᶻ)
✓ Probabilistic output
✗ Vanishing gradient (max 0.25)
✗ Not zero-centred

Tanh

Output: (-1, 1)
(eᶻ - e⁻ᶻ) / (eᶻ + e⁻ᶻ)
✓ Zero-centred
✗ Still vanishes (max 1.0 but tapers)
✗ Expensive (two exp calls)

ReLU

Output: [0, ∞)
max(0, z)
✓ No vanishing (gradient = 1)
✓ Fast to compute
✗ Dead neurons (z<0 → stuck at 0)

Leaky ReLU

Output: (-∞, ∞)
z if z>0 else 0.01z
✓ No dead neurons
✓ Near-zero gradient for z<0
✗ Alpha (0.01) is a hyperparameter

ELU

Output: (-α, ∞)
z if z>0 else α(eᶻ-1)
✓ Smooth, near-zero mean
✓ Better generalisation (research)
✗ Slower (exp for z<0)

Rule of thumb

Use this decision tree:
Output neuron → Sigmoid (binary) or Softmax (multi-class)
Hidden layers → ReLU (default)
Dead neurons? → Leaky ReLU
Research/tuning → ELU or GELU

03 · The Vanishing Gradient Problem

# Sigmoid derivative is at most 0.25 (at z=0)
# After n layers, gradient ≈ 0.25^n

layers = [1, 3, 6, 9, 12]
print("Layer  Sigmoid gradient")
for n in layers:
    print(f"  {n:2d}     {0.25**n:.2e}")

# Output:
#   1     2.50e-01
#   3     1.56e-02
#   6     2.44e-04
#   9     3.81e-06
#  12     5.96e-08
After 12 sigmoid layers, the gradient is 5.96 × 10⁻⁸. The weights in the first layer receive almost zero signal. They can't learn — the network is effectively shallow even though it's deep.
Why ReLU fixes this: For active neurons (z > 0), ReLU derivative = 1.0. The gradient passes through unchanged. A 100-layer ReLU network can still have gradient magnitude = 1.0 at the first layer (assuming all neurons are active).

05 · Brain Exercise

The "dead neuron" problem in ReLU: a neuron whose pre-activation z is always negative will have gradient=0 forever, so its weights never update and it stays dead.

What causes a neuron to get stuck at negative z? And what's the simplest fix?

Answer: A neuron gets stuck when its incoming weights push the pre-activation negative for every training example. This often happens with a bad learning rate (weights overshoot into the negative region) or poor weight initialisation. The simplest fix is Leaky ReLU (alpha=0.01) — a tiny gradient always flows, nudging the weights back even from the dead zone. A higher-tech fix is to use a lower learning rate or add batch normalisation (M25) to keep pre-activations in a healthy range.

06 · Q&A

Q: If ReLU is better than sigmoid for hidden layers, why use sigmoid at all?
Sigmoid is used for the output neuron of a binary classifier — you need a number in (0,1) that can be interpreted as a probability. ReLU output is unbounded [0, ∞), which doesn't represent probability. In hidden layers: ReLU. In binary output: sigmoid. In multi-class output: softmax (which generalises sigmoid to multiple classes).
Q: What is GELU and why is it used in transformers?
GELU (Gaussian Error Linear Unit) = z × Φ(z) where Φ is the Gaussian CDF. It's a smooth approximation to ReLU that "gates" the input probabilistically. GPT, BERT, and most modern transformers use GELU because it achieves better empirical performance on language tasks — the smooth gate seems to match the distribution of language features better than the sharp ReLU gate.
Q: How does batch normalisation help with vanishing gradients?
Batch normalisation (M25) standardises the pre-activations (Z) to zero mean and unit variance before the activation function is applied. This keeps Z in the "non-saturating" region of sigmoid/tanh where gradients are largest. It effectively solves the vanishing gradient problem for sigmoid/tanh, though ReLU + He init remains the practical default.
