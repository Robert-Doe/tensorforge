Module 07 — Decision Trees: Logic the Detective Can Explain

Beginner Decision trees are the most human-readable ML model. They make decisions the same way a detective does: ask a yes/no question, follow the answer, ask another question, reach a conclusion.

00 — How a Decision Tree Works

amount > $500? ├── Yes → overseas_txn == True? │ ├── Yes → FRAUD (95% confidence) │ └── No → hour < 3 AM? │ ├── Yes → FRAUD (78%) │ └── No → LEGIT (82%) └── No → LEGIT (91% confidence)

Each internal node asks a question about one feature. Each branch follows one answer. Each leaf makes a prediction. A prediction is reached by following the path from root to a leaf.

01 — Impurity: How the Tree Chooses Questions

At every node, the tree picks the feature+threshold combination that reduces impurity the most. Impurity measures how mixed the classes are in a node.

Gini Impurity

Gini = 1 - Σ pᵢ²
Node compositionGiniInterpretation
100% class A (pure)0.000No impurity — perfect split
90% A / 10% B0.180Mostly pure
70% A / 30% B0.420Moderate mix
50% A / 50% B0.500Maximum impurity
def gini(y):
    classes, counts = np.unique(y, return_counts=True)
    probs = counts / len(y)
    return 1 - np.sum(probs ** 2)

# Information Gain = parent impurity - weighted average child impurities
ig = gini(y_parent) - (len(y_left)/len(y))*gini(y_left) \
                    - (len(y_right)/len(y))*gini(y_right)

02 — Fitting a Decision Tree

from sklearn.tree import DecisionTreeClassifier, export_text, plot_tree

# Fit (no scaling needed — trees are scale-invariant)
tree = DecisionTreeClassifier(
    criterion="gini",     # "gini" or "entropy"
    max_depth=4,          # limit depth to prevent overfitting
    min_samples_leaf=5,   # leaf must contain ≥ 5 samples
    random_state=42,
)
tree.fit(X_train, y_train)

# Human-readable text representation
print(export_text(tree, feature_names=FEATURE_NAMES, max_depth=3))

# Visual tree diagram (saves to file)
fig, ax = plt.subplots(figsize=(16, 8))
plot_tree(tree, feature_names=FEATURE_NAMES,
          class_names=["Legit","Fraud"],
          filled=True, rounded=True, ax=ax)
fig.savefig("tree.png", dpi=120)

03 — Overfitting: The Depth Problem

A tree with unlimited depth memorises every training sample — it overfits. A tree with too little depth can't capture real patterns — it underfits. Use cross-validation to find the sweet spot.

max_depthTrain accuracyTest accuracyVerdict
1~65%~63%Underfit — too simple
3~85%~84%Good balance
5~95%~86%Starting to overfit
None100%~75%Severe overfitting
from sklearn.model_selection import cross_val_score

depths = [1, 2, 3, 4, 5, 6, 7, None]
for d in depths:
    tree = DecisionTreeClassifier(max_depth=d, random_state=42)
    cv   = cross_val_score(tree, X_tr, y_tr, cv=5, scoring="accuracy")
    print(f"depth={str(d):4s}  cv_mean={cv.mean():.4f}")

04 — Feature Importance

After fitting, each feature gets an importance score: its total Gini reduction weighted by the number of samples it split, normalised to sum to 1.

importances = tree.feature_importances_   # array of shape (n_features,)

# Sort and plot
sorted_idx = np.argsort(importances)[::-1]
for i in sorted_idx:
    bar = "█" * int(importances[i] * 40)
    print(f"  {FEATURE_NAMES[i]:20s} {importances[i]:.4f} {bar}")
Interpretation: High importance means the model relies heavily on that feature. Low importance (near 0) means the tree almost never split on it — that feature may be irrelevant OR correlated with a more important one.

05 — No Scaling Needed

Decision trees are completely scale-invariant. At each split, the tree searches all possible thresholds for each feature. Whether income is in dollars or thousands of dollars, the threshold adjusts automatically. Never scale features before a tree — it has zero effect and adds confusion.

07 — Cost-Complexity Pruning

Post-pruning: grow the full tree, then prune branches whose removal improves generalisation. The ccp_alpha parameter controls how aggressively to prune.

# Find the pruning path
path = tree.cost_complexity_pruning_path(X_tr, y_tr)
ccp_alphas = path.ccp_alphas

# CV over alpha values
from sklearn.model_selection import cross_val_score
cv_scores = []
for alpha in ccp_alphas:
    t = DecisionTreeClassifier(ccp_alpha=alpha, random_state=42)
    cv_scores.append(cross_val_score(t, X_tr, y_tr, cv=5).mean())

best_alpha = ccp_alphas[np.argmax(cv_scores)]
final_tree = DecisionTreeClassifier(ccp_alpha=best_alpha, random_state=42)
final_tree.fit(X_tr, y_tr)

08 — Strengths and Weaknesses

✓ Strengths

  • Fully interpretable: export_text()
  • Handles mixed feature types (numeric + categorical)
  • No scaling required
  • Handles non-linear relationships
  • Fast training and prediction

✗ Weaknesses

  • High variance: tiny data changes → very different tree
  • Axis-aligned splits miss diagonal boundaries
  • Doesn't extrapolate beyond training range
  • Single trees rarely beat ensemble methods
  • Unstable — the starting point for Random Forest

09 — Q&A Brain Check

Q: Why does a tree with unlimited depth get 100% training accuracy?
A: It creates one leaf per training sample (or per group of identical-feature samples). Every training point falls into its own perfectly pure leaf. But those leaves describe noise, not the true signal — they fail completely on new data.
Q: What's the difference between Gini impurity and entropy?
A: Both measure node impurity. Entropy (−Σ pᵢ log₂ pᵢ) has a slightly sharper peak — it penalises 50/50 splits a bit more. In practice they produce nearly identical trees. Gini is faster to compute (no logarithm), so it's the default.
Q: Why do feature importances sum to 1?
A: They are normalised by sklearn. Each node's Gini reduction is weighted by the fraction of samples it processes, then all values across all nodes are summed and divided by the total. This makes importances comparable across trees of different sizes.
Q: How do you handle categorical features in a decision tree?
A: sklearn's DecisionTreeClassifier requires numeric input. Encode categories with OrdinalEncoder (preserves one column) or OneHotEncoder (one column per category). For ordered categories (Low/Medium/High), ordinal encoding is fine. For nominal categories with no order, one-hot is safer.
