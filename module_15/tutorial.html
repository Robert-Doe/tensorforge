Module 15 — Feature Engineering & Pipelines

Preparing evidence correctly before the trial

01 · The Big Analogy

Detective Ada is preparing evidence folders for court. Raw evidence isn't usable as-is: fingerprint match scores range 0-100 but DNA confidence scores range 0-1. If the judge treats these the same, evidence_score dominates purely because of its scale.

She also has location names ("Downtown", "Suburbs") — but ML models need numbers. She creates a separate Yes/No column for each location. That's one-hot encoding.

The critical rule: prepare the evidence folders using only information from previous cases. If she uses statistics from the cases being presented in court to normalise the evidence, she's contaminating the trial. That's data leakage.

sklearn's Pipeline enforces this rule automatically.

03 · Scaling Numerical Features

ScalerFormulaOutput rangeUse when
StandardScaler(x - mean) / std~(-3, 3)Normal-ish distribution; most ML models
MinMaxScaler(x - min) / (max - min)[0, 1]Need hard 0-1 range; neural networks
RobustScaler(x - median) / IQRVariesData with many outliers
Tree-based models (RF, Decision Trees, GB) don't need scaling. They split on thresholds, not distances. Only apply scaling for distance-based (KNN, SVM) or gradient-based models (Logistic Regression, Neural Networks).

04 · ColumnTransformer + Pipeline

from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression

# Different transforms for different column types
preprocessor = ColumnTransformer([
    ("num", StandardScaler(), ["suspect_age", "evidence_score", ...]),
    ("cat", OneHotEncoder(handle_unknown="ignore", sparse_output=False),
            ["location"]),
])

# Chain preprocessor + model — fit() and predict() handle both
pipe = Pipeline([
    ("preprocessor", preprocessor),
    ("model",        LogisticRegression(max_iter=1000)),
])

pipe.fit(X_train, y_train)    # scaler fits on X_train only
pipe.predict(X_test)          # scaler transforms X_test using train stats

05 · Data Leakage — The Silent Killer

Wrong (leaky): 
scaler = StandardScaler()
X_all_scaled = scaler.fit_transform(X)   # ← test data influences the scaler!
X_train, X_test = train_test_split(X_all_scaled, ...)
# The scaler's mean and std were computed using test samples.
# Your CV score is optimistically inflated. Real-world performance will be worse.
Right (Pipeline): 
pipe = Pipeline([("scaler", StandardScaler()), ("lr", LogisticRegression())])
cross_val_score(pipe, X, y, cv=5)
# Inside each fold: scaler.fit(X_train_fold) → scaler.transform(X_test_fold)
# Test data never touches fit(). CV score is trustworthy.

07 · Brain Exercise

The leaky CV score (0.758) is higher than the pipeline CV (0.742). Does that mean leakage always makes models look better?

And: why does adding the location column (4 one-hot dummies) improve performance from 0.742 to 0.750?

Answer 1: Yes — leakage almost always inflates estimated performance because the model gets to "peek" at test data statistics during training. The real-world score will be closer to the pipeline (non-leaky) number.

Answer 2: Location captures information about where crimes happen, which correlates with crime type and solvability. By encoding it numerically, the model can learn "crimes in Downtown are X% more likely to be solved." Dropping location (as M02-M14 did) discarded this signal.

08 · Q&A

Q: What does handle_unknown="ignore" do in OneHotEncoder?
If the test set contains a category the encoder never saw during training (e.g., a new location "Airport"), it returns an all-zeros row for that sample instead of raising an error. The model gets no location information for that case but doesn't crash. This is the safe default for production.
Q: When should I use MinMaxScaler instead of StandardScaler?
Use MinMaxScaler when your model explicitly requires inputs in [0, 1] (e.g., some neural network activation functions, or when you want pixel values). StandardScaler is the better default for most ML models because it's less sensitive to outliers — an extreme value expands the [0,1] range for everyone else in MinMaxScaler.
Q: Can I add PCA inside a Pipeline?
Yes: Pipeline([("preprocessor", preprocessor), ("pca", PCA(n_components=4)), ("model", LogisticRegression())]). The PCA is fit only on training data and transforms test data using training eigenvectors. No leakage.
