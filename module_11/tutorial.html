Module 11 — Support Vector Machines

Don't just find a line — find the widest line

01 · The Big Analogy

Detective Ada is drawing a chalk line on the floor to separate "solved" cases (left pile) from "unsolved" cases (right pile). There are infinitely many lines that correctly separate the piles.

Most detectives draw any line that works. SVM says: find the line that is as far as possible from both piles simultaneously. That gap is called the margin. A wider margin means the line is less sensitive to noise — move a few cases slightly and the boundary still holds.

Gold circles = support vectors — the only training points that matter

02 · The C Parameter — Margin Width vs. Error Tolerance

C valueMarginErrors allowedRisk
Very small (0.01)WideManyUnderfitting — too simple
1 (default)MediumSomeUsually balanced
Very large (100)NarrowAlmost noneOverfitting — memorises training data
# Small C: wider margin, tolerates some misclassification
Pipeline([("scaler", StandardScaler()), ("svm", SVC(kernel="linear", C=0.01))])

# Large C: narrower margin, tries to classify everything correctly
Pipeline([("scaler", StandardScaler()), ("svm", SVC(kernel="linear", C=100))])

03 · The Kernel Trick

What if the data isn't linearly separable? SVM maps the data into a higher-dimensional space where a flat hyperplane can still separate the classes. The kernel function computes the dot product in that high-dimensional space without actually going there.

KernelWhen to useKey hyperparameter
linearLinearly separable, high-dimensional dataC only
rbfNon-linear boundaries (most real problems)C + gamma
polyPolynomial relationships in dataC + degree
# RBF kernel SVM — handles curved decision boundaries
Pipeline([
    ("scaler", StandardScaler()),
    ("svm", SVC(kernel="rbf", C=1.0, gamma="scale", probability=True))
])
gamma="scale" sets gamma = 1 / (n_features × X.var()). This is almost always the right default. Never use gamma="auto" on modern sklearn — it's less well-calibrated.

04 · Why Scaling is Mandatory

# Wrong — SVM sees features on wildly different scales
svm = SVC()
svm.fit(X_train, y_train)   # evidence_score (0-10) vs days_open (0-365)

# Right — scale first, then fit
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

model = Pipeline([
    ("scaler", StandardScaler()),   # makes every feature mean=0, std=1
    ("svm",    SVC()),
])
model.fit(X_train, y_train)   # scaler fits only on X_train (no leakage)

06 · Brain Exercise

Look at the C-sweep output. At C=0.01, accuracy is low. At C=100, accuracy is also lower than C=1. What's happening at each extreme?

Draw the margin for each case. What does a very wide margin mean for the kinds of errors the model makes?

Answer: At C=0.01 the margin is so wide it ignores many training samples — underfitting, high bias. At C=100 the margin is so narrow it fits the training data precisely but doesn't generalise — overfitting, high variance. C=1 hits the sweet spot for this dataset. This bias-variance trade-off exists in every ML algorithm; SVM just makes it unusually visible through the margin metaphor.

07 · Q&A

Q: Why are only some training points called "support vectors"?
The optimal margin is fully defined by the points closest to the boundary — the support vectors. All other training points could be removed and the boundary wouldn't change. This makes SVMs memory-efficient: only the support vectors are stored after training.
Q: Does the RBF kernel always beat the linear kernel?
No. If the data is truly linearly separable (or nearly so), the linear kernel is faster and more interpretable. The RBF kernel only wins when there are curved boundaries in the data. On high-dimensional sparse data (like text), linear SVMs often win because the feature space is already rich enough.
Q: SVM seemed slower to train than LogisticRegression. Why?
Logistic regression uses gradient descent on the full dataset in each iteration. SVM solves a quadratic programming problem that scales roughly O(n²) to O(n³) with number of samples. For large datasets (>100k samples), use LinearSVC or SGDClassifier(loss='hinge') instead.
Q: Why do we need probability=True if we just want class predictions?
You don't — if you only call predict(), drop probability=True and training is 2x faster. Add it only when you need predict_proba() for ROC-AUC or calibrated confidence scores.

Module 12 — Random Forests & Boosting
One decision tree overfits. What if you trained 100 trees on random subsets of data and features, then took a vote? That's a Random Forest — and it's almost always more accurate than any single tree.
