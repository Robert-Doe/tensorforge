Module 06 — K-Nearest Neighbours: Guilt by Association

Beginner The simplest classifier imaginable: look at a suspect's nearest known cases and vote on the label. No training, no parameters to learn.

00 — The Algorithm in Plain English

1

Store ALL training examples (no actual learning happens — KNN is a lazy learner).

2

For a new point x: compute the distance to every stored training point.

3

Select the K training points with the smallest distances.

4

Classification: majority vote among the K neighbours. Regression: mean of their y values.

Critical: KNN is extremely sensitive to feature scale. A feature in thousands (income) will completely dominate a feature in ones (number of children). Always StandardScale before KNN.

                                            stratify=y, random_state=42)

03 — Choosing K

K controls the bias-variance trade-off:

K = 1 (high variance)

  • Each point is its own class
  • Jagged decision boundary
  • Perfect train accuracy, poor test
  • Very sensitive to noise/outliers

K = large (high bias)

  • Smooth, almost linear boundary
  • May miss real patterns
  • More stable but potentially underfit
  • Extreme: K=n → always predicts majority class
from sklearn.model_selection import cross_val_score
import numpy as np

ks = list(range(1, 31, 2))   # odd values to avoid ties in binary classification
cv_scores = []
for k in ks:
    knn = KNeighborsClassifier(n_neighbors=k, weights="distance")
    cv  = cross_val_score(knn, X_tr_s, y_tr, cv=5, scoring="accuracy")
    cv_scores.append(cv.mean())

best_k = ks[np.argmax(cv_scores)]
print(f"Best K = {best_k}")
Rule of thumb: Start with K = √n (square root of training set size). Then tune with cross-validation. Use odd K for binary classification to avoid ties.

04 — Uniform vs Distance Weighting

# Uniform: each of K neighbours gets 1 vote (majority wins)
knn_uni = KNeighborsClassifier(n_neighbors=7, weights="uniform")

# Distance: weight = 1/distance (closer = more influence)
knn_dist = KNeighborsClassifier(n_neighbors=7, weights="distance")

# When does distance weighting help?
# If query is very close to one class-A neighbour but the
# 6 remaining (far) neighbours are class-B:
# Uniform → B wins (6 vs 1)
# Distance → A might win (1 very close point outweighs 6 distant ones)

07 — Strengths and Weaknesses

✓ Strengths

  • Zero training time (lazy learner)
  • No assumptions about data distribution
  • Naturally multi-class
  • Explainable: "these are your 5 closest cases"
  • Adapts to local structure

✗ Weaknesses

  • Slow prediction: O(n·d) per query
  • Must store all training data in memory
  • Breaks down in high dimensions (curse of dimensionality)
  • Must scale features — very sensitive to scale
  • No compact model representation for deployment

08 — Q&A Brain Check

Q: Why does KNN have no "training" phase?
A: KNN is a "lazy learner" — it defers all computation to prediction time. When you call knn.fit(X, y), sklearn simply stores (X, y). When you call predict, it computes distances on the fly. This contrasts with "eager learners" like Decision Trees that build a compact model during training.
Q: What is the curse of dimensionality and why does it hurt KNN?
A: In high dimensions (d > 20), all points become approximately equidistant from any query point. The concept of "nearest neighbour" loses meaning because the nearest and farthest points are almost the same distance away. KNN needs exponentially more data to maintain the same neighbourhood density as d increases.
Q: Why use cross-validation to pick K instead of test set performance?
A: If you tune K using test-set accuracy, you've indirectly trained on the test set — your reported test accuracy will be optimistic. Cross-validation uses only the training set for selection, keeping the test set as a truly unseen final evaluation.
Q: Can KNN handle categorical features?
A: Not directly with Euclidean distance. Options: (1) one-hot encode and use Euclidean; (2) use Hamming distance for binary features; (3) use a mixed distance like Gower distance for mixed-type data. The metric parameter accepts custom distance functions.
