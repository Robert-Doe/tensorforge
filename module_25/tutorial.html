Module 25 — Batch Normalisation & Dropout

Two techniques Ada uses to stop her junior detectives going rogue

01 · The Big Analogy

Recall Ada's junior detectives (conv filters). A problem often emerges during training: some detectives become overconfident — their activation values blow up to the hundreds, overwhelming everyone else's signals. Meanwhile, others shrivel to near-zero and stop contributing. The team becomes unstable. Batch Normalisation is Ada's daily standup meeting: before the report goes to senior staff, every junior detective re-centres their confidence to the same scale. Nobody dominates. Nobody is ignored.

Dropout is Ada's adversarial training exercise: on random days, she randomly tells 40% of her junior detectives to stay home. The remaining detectives have to cover all the cases. The result? The surviving detectives become less dependent on any single colleague — each one learns to be robust on its own. When everyone shows up for the real case (evaluation), the combined team is more reliable than it would have been without the drills.

02 · Batch Normalisation — Mechanics

For each batch of activations entering a BN layer:

# For a single feature map (channel c) across all pixels and batch items:
mu    = mean(activations_c)          # batch mean
sigma = std(activations_c) + 1e-5   # batch std (epsilon for numerical safety)

# Normalise to zero-mean, unit-variance:
x_hat = (x - mu) / sigma

# Learn two parameters: scale (gamma) and shift (beta)
output = gamma * x_hat + beta        # gamma=1, beta=0 at init → pass-through

The learnable gamma and beta let the network undo the normalisation if needed. So BN doesn't force the distribution to always be N(0,1) — it gives the network the option to normalise while still being flexible.

At inference time, BN uses running estimates of mean and variance computed during training (not the current batch's stats). This is why model.train() and model.eval() affect BN behaviour — in eval mode, the frozen running stats are used.

04 · Dropout — Mechanics

# Training (model.train()):
mask    = (random_uniform(shape) > p).float()   # 1 with prob (1-p), 0 otherwise
output  = (input * mask) / (1 - p)              # inverted dropout: scale survivors up

# Inference (model.eval()):
output  = input                                  # no dropout — all activations pass through
Inverted dropout is the standard. By dividing by (1-p) during training, the expected activation magnitude stays the same at train and test time. Without this, you'd need to scale activations by (1-p) at every inference step — easy to forget and a source of silent bugs.

05 · The Code

class DigitCNNwithBN(nn.Module):
    def __init__(self, dropout_p=0.4):
        super().__init__()
        self.conv1 = nn.Conv2d(1, 16, kernel_size=3, padding=1)
        self.bn1   = nn.BatchNorm2d(16)           # one param pair (gamma,beta) per channel
        self.conv2 = nn.Conv2d(16, 32, kernel_size=3, padding=1)
        self.bn2   = nn.BatchNorm2d(32)
        self.pool  = nn.MaxPool2d(2, 2)
        self.fc1     = nn.Linear(32*7*7, 128)
        self.bn_fc   = nn.BatchNorm1d(128)        # 1d — input is (batch, features) not (B,C,H,W)
        self.dropout = nn.Dropout(p=dropout_p)
        self.fc2     = nn.Linear(128, 10)

    def forward(self, x):
        x = self.pool(F.relu(self.bn1(self.conv1(x))))
        x = self.pool(F.relu(self.bn2(self.conv2(x))))
        x = x.view(x.size(0), -1)
        x = F.relu(self.bn_fc(self.fc1(x)))
        x = self.dropout(x)
        return F.log_softmax(self.fc2(x), dim=1)
BatchNorm2d vs BatchNorm1d: BatchNorm2d expects input of shape (batch, channels, H, W) — one gamma/beta per channel. BatchNorm1d expects (batch, features) — one gamma/beta per feature. Using the wrong one raises a shape mismatch error immediately.

07 · Brain Exercise

Batch Normalisation introduces extra learnable parameters: one gamma and one beta per channel. For the BN layers in DigitCNNwithBN:

  • bn1: 16 channels
  • bn2: 32 channels
  • bn_fc: 128 features

How many total BN parameters does the model add? Is it worth it?

Answer: Each BN layer has 2 parameters per unit (gamma + beta). Total BN params:
bn1 = 2×16 = 32  |  bn2 = 2×32 = 64  |  bn_fc = 2×128 = 256  |  Total = 352

The baseline model has 206,922 parameters. BN adds 352 (0.17%). For a 0.23 percentage-point accuracy gain (99.01% → 99.24%), that's a very good trade. In larger networks the accuracy gain from BN is often 2–5% because it enables a 10× higher learning rate, dramatically faster convergence.

08 · Q&A

Q: Why does BN behave differently in train vs eval mode?
During training, BN normalises using the current batch's mean and variance. Each batch is different, so BN adds a form of stochastic regularisation (similar to Dropout). During evaluation you want deterministic predictions, so BN uses running averages of mean and variance accumulated during training — a stable estimate of the population statistics. Calling model.eval() switches this automatically; forgetting it can cause wildly inconsistent test scores.
Q: What happens if the batch size is 1 with BatchNorm?
BatchNorm2d computes statistics over the batch dimension. With batch_size=1, the variance of a single sample is 0 — division by zero (plus epsilon). The result is numerically unstable and practically useless. For batch_size=1 (common in RNNs processing one timestep, or online inference), use Layer Normalisation (nn.LayerNorm) instead, which normalises across features rather than across the batch.
Q: Should Dropout come before or after BN?
Conventionally: BN before Dropout. BN uses the full batch statistics (before dropout zeroes some activations); if dropout came first, BN would compute statistics on a randomly masked batch — inconsistent statistics between train and eval. Putting Dropout after BN ensures BN sees the full, un-masked distribution. Some recent papers argue the order matters less than commonly assumed, but BN → Dropout is the safe default.
Q: In the terminal output, "Before BN: std=0.82" — isn't that already close to 1?
After just one epoch of Adam training, weights have already started converging, so activations happen to be nearly unit-variance for this particular model. Early in training (epoch 0, random weights) or in deeper networks, the pre-BN std can be 5–50×. The bigger benefit of BN is preventing those large deviations from happening in the first place — it keeps activations in a stable range throughout training, so the learning rate doesn't need to be tuned per layer.
