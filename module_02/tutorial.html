Module 02 — Pandas: The Detective's Case File System

Beginner NumPy handles raw numbers. Pandas handles labeled tables — like a spreadsheet that knows Python.

00 — The Two Core Objects

Series

A labeled 1-D array. Like a single column with row labels.

s = pd.Series([3, 7, 2], index=["Mon","Tue","Wed"])
s["Tue"]   # 7

DataFrame

A labeled 2-D table. Rows = samples, columns = features.

df = pd.DataFrame({
    "district": ["North","South"],
    "cases":    [10, 7],
})
df["cases"]   # Series

02 — Selecting Data: loc vs iloc

Critical: loc uses labels. iloc uses integer positions. They look similar but behave differently when the index isn't 0,1,2,...
# Column selection
df["district"]               # one column → Series
df[["district","days_open"]] # multiple columns → DataFrame

# Row selection
df.loc[0]                    # row with label 0
df.iloc[0]                   # row at position 0 (same here)
df.loc[0, "district"]        # single cell by label
df.iloc[0, 1]                # single cell by position

# Slicing
df.loc[0:2]                  # rows 0, 1, 2 (inclusive for loc!)
df.iloc[0:2]                 # rows 0, 1   (exclusive end for iloc)

# Boolean filtering
df[df["days_open"] > 30]
df[(df["days_open"] > 30) & (df["fraud"] == True)]

04 — GroupBy: Split-Apply-Combine

GroupBy is the most powerful Pandas operation. Split the table by a category, apply a function to each group, combine the results.

# Mean cases per district
df.groupby("district")["days_open"].mean()

# Multiple aggregations at once
df.groupby("district").agg(
    n_cases    = ("case_id",  "count"),
    avg_days   = ("days_open","mean"),
    max_days   = ("days_open","max"),
)

# Transform: add per-group statistics back to the original DataFrame
df["district_avg"] = df.groupby("district")["days_open"].transform("mean")

05 — Adding and Modifying Columns

# New column from expression
df["is_urgent"] = (df["days_open"] > 60) & (df["priority"] >= 4)

# Binning: continuous → categorical
df["age_bucket"] = pd.cut(df["days_open"],
                           bins=[0, 30, 90, 180],
                           labels=["Fresh","Stale","Cold"])

# Apply a function to each row/column
df["case_code"] = df["district"].str[:2].str.upper() + df["case_id"].str[-4:]

# Rename columns
df = df.rename(columns={"days_open": "days"})

# Drop columns
df = df.drop(columns=["unnecessary_col"])

06 — Handling Missing Data

df.isna().sum()            # count nulls per column
df.dropna()                # drop rows with ANY null
df.dropna(subset=["col"])  # drop only if this column is null

# Fill with a constant
df["col"].fillna(0)

# Fill with column median (better than mean for skewed data)
df["days_open"].fillna(df["days_open"].median(), inplace=True)

# Fill with group-specific median (even better)
df["days_open"] = df.groupby("district")["days_open"].transform(
    lambda x: x.fillna(x.median())
)
Rule: Always fit imputation statistics (mean, median) on the training set only, then apply them to the test set. Covered in Module 28's full pipeline.

09 — Q&A Brain Check

Q: What's the difference between df.loc[1:3] and df.iloc[1:3]?
A: loc[1:3] returns rows with labels 1, 2, 3 (inclusive). iloc[1:3] returns rows at positions 1, 2 (exclusive end, like Python slicing). When the default integer index is used they look the same — but with custom indices they differ.
Q: Why use fillna(median) rather than fillna(mean)?
A: The median is robust to outliers. If most cases take 10–50 days but a few take 500 days, the mean is pulled high and imputing with it distorts the data. The median stays near the typical value.
Q: What does groupby().transform() do differently from groupby().agg()?
A: agg() returns one row per group. transform() returns the same number of rows as the original DataFrame, with the group statistic broadcast back to each row — useful for adding a per-group mean as a new feature column.
Q: How do you avoid accidentally modifying a view instead of a copy?
A: When filtering and then assigning, use .copy(): subset = df[df["col"]>5].copy(). Without it, Pandas may warn about setting on a copy. Pandas 3.0+ always copies; in 1.x/2.x the "SettingWithCopyWarning" signals this risk.
